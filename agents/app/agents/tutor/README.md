# Tutor: owner Will

**What it does:** runs the student **check-in** (step 2 of a flipped-classroom assignment, `docs/flipped-classroom-plan.md` sections 4 and 5). The student answers each question; a miss opens a tutor scoped to that one question; the miss is **fixed** with the right answer plus a short explanation in their own words. Completion, not correctness, is the grade.

**Kind of system:** a conversational `create_agent` with **read-only** tools. It's the deliberate contrast with the other agents: an agent that is *not allowed to act*. Every state change (answers, fixes, tutor turns, grade) is made by the route in code, through `app/shared/checkin.py`, never by the model.

## Endpoints (all student-facing, `Authorization: Bearer <student JWT from Express>`)

| Route | Body → response |
|---|---|
| `GET /agents/tutor/checkin/{assignment_id}` | `{assignment, practice, unlocked, questions:[Q], signals}`. `questions` is empty until practice unlocks it. |
| `POST .../answer` | `{question_id, option_id? , text?}` → `{question:Q, correct, feedback, signals}` |
| `POST .../fix` | `{question_id, option_id?, explanation}` → `{question:Q, accepted, feedback, signals}` |
| `POST .../chat` | `{question_id, message}` → `{reply, question:Q}` (question `unanswered` or `needs_fix`) |
| `GET .../chat/{question_id}` | `{messages:[{role, content}]}` |

`Q = {question_id, number, text, kind:"choice"|"explain", options?:[{option_id, text}], status, first_answer, tries, help_level, last_feedback, can_reveal}`. It never contains the right answer. Options are shuffled per student exactly like Express's `seededShuffle`. Select-all questions (never generated by the games agent) add `multi: true` and take `option_ids: [...]`, checked as an exact set.

Errors: 401 no/bad token · 403 not enrolled, practice not unlocked yet, or past the due date (POSTs only; GETs still work) · 404 not a check-in · 400 wrong state (already answered, nothing to fix, option from another question) · 422 `{detail}` not an honest try (`checkin.honest_try`: empty, "idk", same as last time, explanations under 4 words), MC answer without an option.

## Rules enforced in code

- **Answer:** MC is an exact check (no model call). An "explain" answer is judged by the explain-back judge.
- **Fix:** MC needs the right option **and** an accepted explanation; explain questions need an accepted explanation. Every honest fix attempt counts as a try, so brute-forcing MC costs a fresh reason each time.
- **Tutor mode** (`assignments.tutor_mode`): the answer only enters the model's context when `checkin.may_reveal()` is true (`answer_after_tries` mode, after `tutor_reveal_after` honest tries). That turn may walk through the answer and must end by asking the student to explain it back (code appends the request if the model forgot); it sets `help_level = "explained"`. Every other turn is `"hint"`.
- **Teacher instructions:** `assignments.ai_params`, if set, go into the prompt.
- **Transcripts:** both turns are saved with `question_id` (`checkin.save_chat`) and kept; the briefing and misconception finder read them.

## Guards

- **Answer guard** (`guard.py`, ported from `backend/routes/ai.ts`): same normalisation and word-set Dice coefficient, same 0.72 threshold, applied to the tutor's *reply* against the answer key (right option, model answer, rubric). Blocks on a verbatim answer, any sentence or answer-length window with Dice ≥ 0.72, or (MC) the right option's distinctive words ("membrane" for "Cell membrane"). Runs as `AnswerGuardMiddleware` inside the agent and again on the final text. Off only when `may_reveal()` is true. A blocked reply is swapped for the no-AI hint.
- `BlockedActionsMiddleware` (shared hard blocks), `PIIMiddleware` for emails and phone numbers (redacted before the model sees them), `ModelCallLimitMiddleware` (4 model calls per message).
- Judge feedback goes through the same guard, so "what's missing" never states the answer.

## Explain-back judge (`judge.py`)

Checks the explanation against `explain_rubric` (fallback: the model answer, or the right option's text). An explanation that mostly repeats the question is rejected without a model call.
- **Model:** one structured-output call `{accepted, missing_idea}`, lenient on wording, rejects wrong, off-topic or answer-without-a-reason.
- **No-AI:** content-word overlap with the rubric (lowercase, stopwords dropped, crude 5-letter stems; words the question already uses don't count). Accepts at ≥ 40% of the rubric's key words and at least 2 (or all, if fewer). For MC without a rubric (the right option is already required), two meaningful words of reason are enough. A near miss names one missing word ("You're close. Say more about "enters".") only when the rubric has 3+ key words, so it can't give the idea away.

## No-AI mode

Used when there's no key for the configured model, when `AGENTICTA_TUTOR_OFFLINE=1` (environment or this folder's `.env`), or for one turn when a model call fails (errors, quota, timeout after 30 s with 1 retry). Never a 500.
- **Tutor:** searches the unit's notes with the question plus the student's message and replies with a short Socratic nudge and the most relevant line of the notes, with the answer blanked out (`____`). It reminds the student what they answered first. When `may_reveal()` is true it shows the answer and the key idea and asks them to explain it back.
- **Judge:** the overlap rule above.

## Pointing it at a model you have

`config.yaml` says `tutor.main = openai:gpt-6.2-sol`. Without `OPENAI_API_KEY` the tutor runs in no-AI mode. To use Gemini instead, put this in `agents/app/agents/tutor/.env` (personal override, nothing shared changes) and restart the agents service:

```
MODEL_MAIN=google_genai:gemini-3.5-flash-lite
GOOGLE_API_KEY=...        # or leave it out to use the key in the project .env
```

`GET /agents/tutor/info` shows the model in use and whether its key is set. Expect about 1 judge call per explain answer and 1-3 calls per tutor message (a search, then the reply).
